Switch M3TERS · Full-stack engineer: built end to end (API, dashboard, gateway agent)

2026

Switch M3TERS collects telemetry from Switch meters across LoRaWAN gateways. A Go agent on each gateway reads ChirpStack MQTT, keeps only registered meters on FPort 4, buffers to disk and forwards over HTTPS. The Node.js/Express API decodes the 97-byte Cumulus telemetry frame, stores raw events, measurements and hourly rollups in MongoDB, and streams updates to a React dashboard over Socket.IO. Ingestion is idempotent, and energy deltas survive meter restarts and late readings. End-to-end tests with the release binary covered two simulated meters, a 50-second API outage and an agent restart, with no lost or duplicated readings.

  • Go gateway agent: MQTT filtering, disk-buffered delivery, systemd service, and Ed25519-signed self-updates for amd64, arm64 and armv7 with automatic rollback
  • Dashboard: live per-phase readings, history charts, analytics (consumption, demand, power quality, RSSI/SNR, reliability), CSV/PDF reports, light and dark themes
  • Firmware updates over the air: upload signed meter firmware and run ChirpStack FUOTA campaigns per gateway; meters confirm the new version in their telemetry
  • Security: separate admin and agent APIs, hashed gateway credentials, bcrypt, rate limits, Zod validation, roles and invitations, audit logs
  • No lost or duplicated readings through an API outage and an agent restart in end-to-end tests

Tech: React, Vite, Recharts, Node.js, Express, MongoDB, Socket.IO, Go, MQTT, ChirpStack, LoRaWAN FUOTA, Ed25519

Eneon Tunnels · Founder and engineer, Eneon Technologies: built end to end

tunnels.eneontechnologies.com

Eneon Tunnels is Eneon Technologies' first product. A small Go agent on each device keeps one outgoing, encrypted WebSocket to the relay, so it works behind any router or mobile network and nothing on the device is exposed to the internet. From the dashboard, owners open ChirpStack, Node-RED, router pages or any web app on the device, start an SSH session in the browser (xterm.js, with a touch key bar for phones), talk to an Arduino or ESP32 over a serial console, restart or shut down the device, and watch RTSP or ESP32-CAM streams. Any TCP port can also be brought to a laptop with `eneon connect`. Access can be shared as a link with an optional password and expiry, or with teammates by email. One command installs the agent on Linux, Raspberry Pi, macOS or Windows. It then updates itself with signed releases and rolls back automatically if a new version can't reach the relay.

  • Go relay and agent: one outgoing encrypted WebSocket per device, so it works behind NAT and mobile networks with no inbound ports
  • Web apps through the relay, SSH terminal in the browser, serial console, any TCP port via `eneon connect` / ProxyCommand
  • Sharing: per-app links with password and expiry, or per-device sharing by email limited to chosen ports
  • Signed self-updates for 6 platforms with automatic rollback; removing a device makes its agent uninstall itself
  • Accounts with email confirmation and password reset, per-user device limits, and an admin console

Switch Cumulus · Firmware engineer: lead developer

2026

Switch Cumulus measures energy with an ATM90E36A metering IC and reports Ed25519-signed, nonce-protected usage readings over LoRaWAN (OTAA, Class C). A backend can switch the customer's load through a relay with downlinks. A custom bootloader installs signed firmware updates sent over LoRaWAN FUOTA, survives power cuts mid-install and rolls back automatically if the new firmware cannot join the network. Optional FPort 4 telemetry carries every phase's voltage, current, active and reactive power, power factor, neutral current, frequency and temperature for the Switch M3TERS dashboard.

  • Signed-image bootloader: backup, power-cut-safe install, automatic rollback, downgrades refused
  • Device-unique Ed25519 key generated from the hardware TRNG; signed reports with server-issued nonces for replay protection
  • Three-phase metering with selectable phase mode, run-time PGA settings and guided serial calibration
  • Reliability: no heap, bounds-safe printf, stack guard, crash reports, watchdog and automatic LoRaWAN re-join

Tech: C, STM32WL55, ATM90E36A, LoRaWAN, FUOTA, Ed25519, Bootloader, CMake, ChirpStack

Switch Maxwell · Firmware engineer: lead developer

2024-2026

Switch Maxwell measures RMS voltage on the STM32WL55's ADC and current through a dedicated STM32G030 peak-detector co-processor over I2C, then computes power and energy (kWh). Each meter has its own Ed25519 identity, and every energy report is signed and bound to a server-issued nonce so the backend can verify where a reading came from and reject replays. Energy the server has not acknowledged carries over to the next report. Downlinks switch the isolator, change the reporting interval, set the nonce and location, or reboot the meter. Firmware updates arrive over LoRaWAN FUOTA and are installed by a signed-image bootloader with rollback.

  • Two-MCU design: STM32WL55 meter firmware plus an STM32G030 current peak detector over I2C
  • Ed25519-signed, nonce-bound energy reports with carry-over of unacknowledged energy
  • Firmware updates over the air (ChirpStack FUOTA) with a signed-image bootloader, rollback and product checks
  • Self-healing link: automatic re-registration and re-join, crash protection, bench self-test

Tech: C, STM32WL55, STM32G030, Generic Node SE, LoRaWAN, FUOTA, Ed25519, I2C
